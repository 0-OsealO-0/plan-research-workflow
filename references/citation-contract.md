# Citation Contract

引用不是排版问题，是事实问题。一个编造的 DOI、一条不存在的文献、一处对不上的页码，
在评审眼里比论证薄弱严重得多——它让整篇论文的可信度归零。

本文件规定本流程唯一允许的引用做法。

## 1. 单一事实源：`citations.csv`

所有引用先进入一个 CSV，再进入正文。列定义：

| 列 | 必填 | 含义 |
|---|---|---|
| `id` | 是 | 正文引用编号 `[1]`、`[2]`……，从 1 连续编号 |
| `authors` | 是 | 作者，半角分号分隔：`Zhang S; Li Y` |
| `year` | 是 | 出版年，四位数字 |
| `title` | 是 | 题名，原语言 |
| `venue` | 是 | 期刊 / 出版社 / 会议 / 学位授予单位 |
| `doi_or_url` | 二选一 | DOI（`10.xxxx/...`）或可访问的稳定 URL |
| `page` | 条件必填 | 期刊页码 `101-120`、专著引用页、会议页码 |
| `verified_by` | 是 | 核验人（写 `lead` 或本人姓名）；空 = 未核验 |
| `verified_on` | 是 | 核验日期 `YYYY-MM-DD` |
| `supports` | 是 | 这条文献支撑正文哪个具体主张（写那句话，不写"相关研究"） |
| `type` | 否 | GB/T 7714 类型码 `J/M/C/D/R/S/P/N/EB-OL`；`import_refs.py` 会自动填，`export_docx.py` 用它渲染文献类型 |

模板见文件末尾。没有这个文件，不进入写作步骤。

`import_refs.py` 会把 RIS / BibTeX / CSL-JSON 导出写成上表结构，`type` 按来源映射，
`verified_by` 留空——**导入不等于核验**，它只把"候选"变成"待核验的行"。

## 2. 四条硬规则

1. **没有标识符的条目不许进文献表。** 期刊/会议/学位论文/电子资源必须有 DOI 或 URL；
   专著/标准/专利至少要有出版者、版次或标准号、页码。缺标识符 = 无法核对 = 不可引用。
2. **没有核验记录的引用不许进正文。** `verified_by` 为空的行，正文不得使用对应编号。
3. **核验不了就删，不改写成模糊引用。** 不要用"有研究表明"替代一条查不到的文献；
   改为引用你能核验的文献，或把该主张降级为常识性陈述并明确其性质。
4. **表格只能由两种来源填入**：用户提供并确认的来源，或一次真正打开条目的核验动作。
   不得凭记忆、凭"格式看起来对"填表。一批整齐得可疑、字段齐全却没有阅读痕迹的引用，
   按未核验处理。

## 3. 核验怎么做

```bash
python scripts/verify_refs.py --csv citations.csv
```

脚本通过 `https://doi.org/<DOI>` 的内容协商取回 CSL-JSON，比对题名、年份、
第一作者、刊名和页码，逐条给出：

| 状态 | 含义 | 处理 |
|---|---|---|
| `OK` | 解析成功且字段一致 | 可写 `verified_by` |
| `PARTIAL` | 解析成功，个别字段（刊名/页码）不一致或缺失 | 人工看一眼，多数是格式差异 |
| `MISMATCH` | 题名/年份/作者对不上 | 条目错误或 DOI 张冠李戴，改正或删除 |
| `UNREACHABLE` | DOI 解析失败（404、超时） | 视为不存在，删除，不得改写成模糊引用 |
| `MANUAL` | 无 DOI/URL 但有出版信息与页码（专著/标准） | 对着书/标准人工核对 |
| `NO_ID` | 什么标识都没有 | 补标识或删除 |

脚本只回答"这条文献是否存在、字段是否一致"。**"它是否支持这句话"脚本回答不了**，
必须读摘要或正文后人工判断。

然后对每一条：

1. 用 DOI 打开 `https://doi.org/<DOI>`，确认题名、作者、年份、期刊卷期页码一致。
   打不开或解析到别的文章 = 该条目作废。
2. 没有 DOI 时，打开出版社/期刊页面或图书馆目录，核对题名、作者、年份、页码。
3. 记录你实际看到的东西（`verified_on`），不要凭记忆填写。
4. 只核验到摘要、没看到正文的，在 `supports` 里写清"仅据摘要"，不要声称摘自正文某页。
5. 二手引用（转引自他人）必须写明"转引自"，并尽量回溯原文；回溯不到就降级处理。

**AI 生成的文献列表一律视为未核验。** 语言模型会生成看似合理、实际不存在的题名、作者和 DOI，
批量出现的"完美引用"是典型症状。核验成本由使用 AI 的人承担，不转移给审稿人。

## 4. 与 GB/T 7714 的对应

`citations.csv` 是事实层，文献表是格式层。按类型取字段：

| 类型 | 类型标识 | 文献表必须包含 |
|---|---|---|
| 期刊论文 | `[J]` | 作者. 题名[J]. 刊名, 年, 卷(期): 起-止页. |
| 专著 | `[M]` | 作者. 书名[M]. 版次. 出版地: 出版者, 年: 引用页. |
| 学位论文 | `[D]` | 作者. 题名[D]. 城市: 授予单位, 年. |
| 会议论文 | `[C]` | 作者. 题名[C]//论文集名. 出版地: 出版者, 年: 页码. |
| 标准 | `[S]` | 标准号 标准名称[S]. 出版地: 出版者, 年. |
| 专利 | `[P]` | 专利权人. 专利名: 专利号[P]. 公告日期. |
| 电子资源 | `[EB/OL]` | 作者. 题名[EB/OL]. (发布日期)[引用日期]. URL. |
| 报纸 | `[N]` | 作者. 篇名[N]. 报纸名, 出版日期(版次). |

英文文献用 `et al.`，中文用 `等`；作者超过 3 人只列前 3 人加"等/et al."。
细节规则见 `references/gbt7714.md`。

## 5. 脚本校验

```bash
python scripts/check.py draft.md --type course --citations-csv citations.csv
```

- `[ref] [n] 缺 DOI/URL/页码` → 该条目无法核对，补标识符或删除。
- `[ref] [n] 缺出版年` / `缺文献类型标识` → 格式不完整，按上表补。
- `[citation] 正文引用但文献表缺失：[n]` → 正文和文献表不一致，CRITICAL。
- `[csv] 正文引用了 citations.csv 中不存在的编号：[n]` → 该引用没有事实来源，CRITICAL。
- `[csv] 引用的条目未核验（verified != y）：[n]` → 未填 `verified_by`，核验后再写。

脚本只能证明"字段齐全、编号一致"，不能证明"文献真实存在且支持该主张"。
后者由 `verify_refs.py` 完成一半（存在与字段），另一半（是否支持该句）必须由人读。

## 5.1 真实性核验

```bash
python scripts/verify_refs.py --csv citations.csv --out citations_checked.csv
python scripts/verify_refs.py --csv citations.csv --only 3,5 --delay 1
```

- 默认每条间隔 1 秒，避免触发 doi.org 限流；一次几十条可以接受。
- `--only` 只复核指定编号，用于改完几条后增量核验。
- `--strict` 让 `PARTIAL` 也判失败，用于终稿前的最后一轮。
- `--offline` 只做格式检查，不联网；离线时不得声称"已核验"。
- 退出码 1 表示有 `MISMATCH` / `UNREACHABLE` / `NO_ID`，此时禁止交稿。

## 6. 何时停

- 写作前没有 `citations.csv`：先建表，向用户要文献来源，不凭空补。
- 发现编造条目：整表复核，不要只删被发现的那条。
- 用户要求"多加几篇参考文献凑数"：拒绝，并说明这属于学术不端风险。
